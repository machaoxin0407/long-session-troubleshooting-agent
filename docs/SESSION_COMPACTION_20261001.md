# 同一会话上下文压缩升级（2026-10-01）

本次在原 SQLite 会话记忆上增加结构化模型摘要与 token 估算预算。仅限同一 `session_id`，
没有跨会话画像、共享或检索。`/chat`、`/v2/chat` 请求与响应形状保持兼容。
不修改数据集、检索流程或既有正式验收结论，不启动历史外部服务任务。

## 处理流程

1. 成功回答后原子追加用户问题和最终交付文本到原文归档；失败请求不追加。
2. 下一次提问时读取同一会话归档。历史尚未超预算时直接使用原文，
   不按单条 1000 字符截断，不调用摘要模型。
3. 超预算时保留最近 `CHAT_SESSION_HISTORY_LIMIT / 2` 轮。历史中过大的消息用带省略标记的
   预览替换；原始记录保留在 SQLite，可在同一会话按问题检索。
4. 将较早历史交给已经配置的首个回答模型路由，输出结构化 JSON。
   单独列出设备型号、用户确认的现象、否定条件、用户更正、已尝试操作、待解决问题、未核验客服建议。
5. 每个摘要条目必须关联轮次、角色和连续的原话片段。校验字段、实际轮次、角色及逐字引用；
   用户事实类字段不得引用助手来源。优先保留更正与条件，超预算时仅保留完整条目及其引用。
6. 超时、路由忙、无路由、模型错误、不完整生成、无效 JSON 或引用校验失败时，使用本地规则摘录。
   摘要失败不令整个回答失败；存储故障仍返回 503。请求取消仍传播取消，不能吞掉后继续写摘要。
7. 缓存摘要和压缩边界。后续将摘要与新原文组合，直到再次超预算。
   再次压缩从归档原文重建，避免反复“摘要的摘要”造成累计漂移。
8. 摘要或省略消息存在时，按当前问题回查最多 3 个同会话相关轮次，优先展示匹配的原句。
   已完整显示的近期消息不重复召回。摘要和旧回答均不作为知识库证据，本轮回答仍须依据新检索证据核验。

摘要生成期间不持有 SQLite 写锁。写回时比较归档首尾轮次，拒绝并发追加、过期、
清空或重建导致的过时快照；必要时再读一次，使用规则回退。不恢复已经清除的摘要。
同会话并行回答依然可能从同一快照推理，写入按完成顺序，客户端应串行提问。

## 预算与模型配置

没有增加或下载 tokenizer、摘要模型或框架依赖。当前用 UTF-8 字节数作保守 token 估算，
对常见按字节编码的 tokenizer 留出余量，但不是任意上游 tokenizer 的精确计数。
预算针对会话记忆，包含近期消息及其来源、摘要、回查和固定前缀预留；
不包含当前问题、系统提示、当前检索证据和本轮工具上下文，不能宣称保证完整模型请求一定不溢出。

| 环境变量 | 默认值 | 含义 |
| --- | --- | --- |
| `CHAT_SESSION_CONTEXT_TOKENS` | `6000` | 会话记忆估算总预算 |
| `CHAT_SESSION_RECENT_TOKENS` | `2800` | 压缩后近期原文与预览预算 |
| `CHAT_SESSION_SUMMARY_TOKENS` | `1400` | 含引用与标签的摘要预算 |
| `CHAT_SESSION_RECALL_TOKENS` | `800` | 回查预算，含标签预留 |
| `CHAT_SESSION_SUMMARY_INPUT_TOKENS` | `16000` | 单次摘要原文输入预算；归档过大时优先选择较新的旧轮次 |
| `CHAT_SESSION_MODEL_SUMMARY` | `1` | 启用模型摘要；`0` 使用 token 预算和规则回退 |
| `CHAT_SESSION_SUMMARY_MODEL` | 空 | 空则复用首个已配置路由的模型；指定值必须受该路由支持 |
| `CHAT_SESSION_SUMMARY_TIMEOUT_S` | `4` | 单次摘要总时间上限，不重试；同时受请求 deadline 限制并预留 5 秒 |
| `CHAT_SESSION_SUMMARY_MAX_TOKENS` | `1200` | 上游摘要输出 token 上限 |

总预算须不少于近期、摘要、回查预算之和再加 768；近期预算还须能容纳来源标记。
模型摘要默认会增加一笔已有模型路由的调用，只在需要压缩时发生。
超长响应通过异步 HTTP 的总时间限制取消，不能以持续传输绕过单次超时。
无可用并发槽时立即回退，不抢占已使用的回答槽。

`CHAT_SESSION_DB_PATH`、`CHAT_SESSION_TTL_S=3600`、会话 LRU 容量 500、
每会话原文 200 轮／200 万字符、清空 API 等保留策略继续生效。
旧数据库无损增量创建 `chat_memory_compactions` 表，不覆盖旧归档。
归档淘汰导致首轮变化时使摘要缓存失效，避免摘要持续携带已淘汰来源。
清空、TTL 和 LRU 级联删除摘要缓存。极端超过原文容量的单轮仍显式截断，不能保证该轮原文完整。
旧字符预算仍用于兼容原有摘录状态；API 实际上下文从原文重建，使用上述 token 估算预算。

## 来源与实际取舍

- [Deep Agents](https://www.langchain.com/blog/context-management-for-deepagents)：结构化摘要、原文独立保存和按需恢复。
  [LangChain 摘要源码](https://github.com/langchain-ai/langchain/blob/master/libs/langchain_v1/langchain/agents/middleware/summarization.py)
  以目标、摘要、产物、下一步组织状态；本项目按设备客服字段调整，未引入框架。
- [Mastra](https://mastra.ai/docs/memory/observational-memory)：近期原文与较早观察分层、来源关联。
  本项目没有复制后台 Observer/Reflector，而是在请求前按预算压缩、从归档重建摘要。
- [Google ADK](https://adk.dev/context/compaction/)：token 触发与近期原文保留；本项目预留近期窗口和原文回查。

这是借鉴架构后的本项目实现，不代表这些项目的性能复现。逐字引用校验只能证明来源存在，
不能证明模型改写与原话语义完全等价；摘要仍可能遗漏条件或解释错误，需要回答阶段证据核验和质量评测。
回查仍为词法匹配，同义改写或纯代词可能漏召回；未接入语义向量库、跨会话检索、附件归档或模型内部 KV 压缩。
摘要输入超限时不保证所有较早轮次进入模型，但归档保留范围内仍可按问题回查。

## 验证

离线使用模拟模型和 HTTP MockTransport；不访问真实模型端点或生产数据。
覆盖原文保留、摘要缓存与重启、来源校验、失败回退、超长 Unicode、回查预算、
并发追加与清空不恢复旧摘要、归档淘汰、请求取消、两种模型协议及总时间限制。
真实模型摘要质量与回答效果尚未做在线 A/B 评测。
