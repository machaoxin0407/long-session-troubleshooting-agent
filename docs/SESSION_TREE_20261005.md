## 已实现范围

同一 `session_id` 内，对归档文本分块、聚类并生成摘要，再对摘要反复聚类、生成更上层摘要，直到一个根或达到层数上限。支持从根逐层检索，也支持将原文层及所有摘要层放在一起检索。未引入跨会话记忆，也未重建手册或视频 RAG 索引。

核心代码：`session_tree.py`；存储：`session_memory.py`；API 接入：`api_server.py`。

## 构建流程

1. 历史足够短时直接保留原文，不建树，也不调用摘要模型。
2. 历史超过记忆预算时，保留近期 3 轮。较早原文及被裁剪/移出窗口的近期消息进入树。
3. 按 UTF-8 字节预算切块，每个叶节点保存轮次、角色、原文字符偏移和完整块内容。叶数过多时增大块长，覆盖全部保留原文，而不是丢弃旧块。角色不会跨块混合。
4. 默认使用英文词/型号/中文双字的哈希 TF-IDF 向量，以及容量受限的球面 k-means。每组最多 4 个子节点；退化向量也保证节点数逐层减少。无需新增生产依赖。
5. 每层以子节点文本（上层输入是下层摘要）生成父摘要。原文引用穿过各层仍指向叶节点。模型只能引用该组已提供的后代原文片段；逐字校验来源，不接受虚构节点、重复节点、无来源或超预算输出。
6. 按层批量调用既有回答模型，默认最多 3 次、每次最多 4 秒、总推理预算 8 秒，为当前回答保留至少 5 秒。批量输入超过预算的组或未得到有效输出的组使用有来源的本地摘录。
7. 树以压缩 JSON 写入 SQLite 新表 `chat_memory_trees`。构建时不持有数据库写锁；写入前校验原文快照，发生追加、清空、过期或淘汰则拒绝旧结果，并最多重新读取一次。

树为硬聚类结构，每个子节点只有一个父节点。不是 RAPTOR 原实现的 UMAP/GMM 软聚类复刻，也未宣称取得其论文效果。直接借鉴的是 [RAPTOR 官方项目](https://github.com/parthsarthi03/raptor) 的“递归聚类摘要 + 两种树检索”设计。

## 两种检索

| 模式 | 检索行为 | 权衡 |
|---|---|---|
| `collapsed`（默认） | 原文节点和所有摘要层一起按查询相似度排序，选 top-k | 无父层筛选造成的漏召回，但候选可能包含重复的父子内容 |
| `traversal` | 根层选 top-k，只展开选中节点的孩子，各层继续选 top-k；汇集访问的各层候选再按相似度排序 | 减少候选范围，但被剪掉的分支不会进入树检索结果 |

预算只允许一部分候选进入模型上下文，两种模式都不是把全部树文本发送给模型。“所有层检索”指候选包含所有层。没有匹配词的本地查询回退到根概览。

关键词原文回查独立保留，最多 3 轮，优先展示相关句子。这能补回摘要遗漏的细节，逐层树检索剪掉的原文也可能经此通道回查。最新原文和当前更正仍优先；客服旧建议明确标记未核验。

## 使用

`POST /chat` 和 `POST /v2/chat` 均接受新的可选字段，响应结构保持兼容：

```json
{"question":"ZX900 的充电异常之前试过什么？", "session_id":"demo", "memory_retrieval":"collapsed"}
```

```json
{"question":"ZX900 的充电异常之前试过什么？", "session_id":"demo", "memory_retrieval":"traversal"}
```

不传该字段时使用 `CHAT_SESSION_TREE_RETRIEVAL`。非法值为 422。`DELETE /v2/chat/sessions/{session_id}` 同时清除树和原文。存储仍采用最后成功写入后 1 小时 TTL、最多 500 会话、每会话 200 轮/200 万字符；不提供永久记忆。

| 配置 | 默认 | 说明 |
|---|---:|---|
| `CHAT_SESSION_TREE_ENABLED` | 1 | 0 恢复原有单层摘要上下文 |
| `CHAT_SESSION_TREE_RETRIEVAL` | collapsed | 默认检索方式 |
| `CHAT_SESSION_TREE_CHUNK_TOKENS` | 800 | 初始块预算，UTF-8 字节估算 |
| `CHAT_SESSION_TREE_MAX_LEAVES` | 512 | 必须至少为 `CHAT_SESSION_ARCHIVE_TURNS × 2`，以容纳所有消息 |
| `CHAT_SESSION_TREE_BRANCH_SIZE` | 4 | 每组最多子节点数 |
| `CHAT_SESSION_TREE_MAX_LEVELS` | 8 | 最多摘要层数，另有第 0 层原文；达到上限允许森林 |
| `CHAT_SESSION_TREE_MODEL_CALLS` | 3 | 一次重建最多模型请求数，0 全部使用本地摘录 |
| `CHAT_SESSION_TREE_BUILD_TIMEOUT_S` | 8 | 构建中的总推理预算，不是整个请求超时 |
| `CHAT_SESSION_TREE_TOP_K` | 3 | 全层 top-k 或逐层 beam 宽度 |

摘要模型开关、模型选择、输入预算继续使用 `CHAT_SESSION_MODEL_SUMMARY`、`CHAT_SESSION_SUMMARY_MODEL`、`CHAT_SESSION_SUMMARY_INPUT_TOKENS` 等已有配置。总历史管理预算仍为 6000，近期窗口 2800、树检索窗口 1400、原文回查 800，另预留格式和历史说明开销。该预算不包括当前问题、系统提示、手册和视频检索内容；不是模型精确 tokenizer 计数。

服务内部 trace 增加 `session_memory_tree`：检索模式、层数（含原文层）、节点数、实际加入上下文的节点 ID/层号、向量方式、模型生成节点数。未建树时为 null。此字段不新增公开回答证据或 citations。

## 向量扩展和独立使用

`MemoryTree.build(records, settings=TreeSettings(), summarizer=callback, embedder=callback)` 可直接构建树；records 使用 `id/question/answer`。`retrieve(question, mode='collapsed'|'traversal', top_k=3)` 返回节点和相似度；`dump()/load()` 可保存并恢复。

可注入语义向量函数 `embedder(texts, *, deadline_ts)`，返回等长、有限的二维向量；调用方必须保证同一模型、向量维度、截止时间和取消处理。构建某层失败则整个树重建为本地词项空间，不混合两种向量。语义树恢复时需要相同 embedder；查询服务失败时，会话上下文使用本地向量回退。

API 默认使用本地词项向量。设置 `CHAT_SESSION_TREE_EMBEDDING=semantic` 后，优先读取 `CHAT_SESSION_TREE_EMBEDDING_BASE_URL/API_KEY/MODEL`，逐项兼容原 `EMBEDDING_*`；超时默认为 4 秒（一次调用全部批次的总时间）。Qwen3.7 每批最多 20 条、其他模型最多 32 条，每条最多 8192 UTF-8 字节；原文叶完整保留。同批重复文本只向量化一次，建树和查询期间复用连接，结束即释放。不重试、可取消、忙时回退。本地词项向量不代表真实语义路径成功。

树摘要适配器使用 `reserve_s=0`，直接遵守构建截止时间；构建层统一为最终回答预留 5 秒。旧单层摘要适配器继续默认预留 5 秒。对注入回调不再传递额外延后的截止时间。

本地对照评测、合成样例、语义服务配置与线上调用上限见 [联调与评测说明](SESSION_MEMORY_EVALUATION_20261005.md)。

## 已知限制与验证边界

- 原文引用校验能证明引用存在，不能证明模型摘要与引用在语义上完全一致；摘要保持未核验。
- 2026-10-08 增加关键型号、错误码、操作名称与所选引文的对应校验及否定状态反转检查。拒绝后保留有来源摘录并记录回退原因；这些规则仍不能替代完整语义审核。缓存签名 tree-v4 使旧摘要重新构建。
- 上层摘要会损失细节。每节点最多 8 个引用，摘要模型引用的是提供的有限原文片段；完整叶文本和原文回查继续保留。
- 原文变化或构建配置/模型签名变化会重建整棵树；切换查询或检索模式不重建。尚未实现局部增量重聚类。
- 推理预算到期后仍完成有界本地聚类/摘录；外部注入回调自身必须遵守 deadline。每层并非所有组都调用模型。
- 模型失败时本地摘录生成完整拓扑，不代表摘要或回答质量等同模型成功路径。
- 本地测试使用伪造摘要/向量和 HTTP MockTransport，不访问真实模型或生产数据；全量回归不替代外部质量与性能验收。
